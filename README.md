# Needwing plugins

Client plugins and registry metadata for [Needwing](https://needwing.ai) — research,
comparisons and recommendations with grounded evidence, served over the Model Context
Protocol.

- Remote MCP endpoint: `https://needwing.ai/mcp` (Streamable HTTP; MCP `2026-07-28` and the
  earlier initialize eras)
- Authentication: OAuth 2.1 (PKCE S256; CIMD/DCR) discovered automatically from the
  endpoint's `401 WWW-Authenticate` resource metadata — every manifest here is header-free,
  so the client runs the OAuth sign-in on first use — or a static
  `Authorization: Bearer` key (a named key `afk_…` or a workspace key)
- Caller tools (scope `research`): `needwing_ask`, `needwing_status`, `needwing_reply`,
  `needwing_evidence`, `needwing_stop`
- No account yet? The sign-in page offers **“Try without an account”** (research-only,
  small daily quota), or run `client.py setup` from
  [the connect guide](https://needwing.ai/connect)

This repository packages one plugin (`needwing`) for several clients plus the official
[MCP Registry](docs/PUBLISHING.md) entry (`server.json`).

## Install

### Claude Code (and Grok Build)

```bash
claude plugin marketplace add actionflow-team/needwing-plugins
claude plugin install needwing@needwing
```

or inside a session: `/plugin marketplace add actionflow-team/needwing-plugins` and
`/plugin install needwing@needwing`. Grok Build reads Claude Code marketplaces, plugins and
skills automatically (see
[xAI docs](https://docs.x.ai/build/features/skills-plugins-marketplaces)), so the same
commands work there.

### Codex

```bash
codex plugin marketplace add actionflow-team/needwing-plugins
codex plugin add needwing@needwing-plugins
```

Without plugins, add the remote server directly (OAuth: run `codex mcp login needwing`
afterwards; key: export `NEEDWING_API_KEY` first):

```toml
# ~/.codex/config.toml
[mcp_servers.needwing]
url = "https://needwing.ai/mcp"
# bearer_token_env_var = "NEEDWING_API_KEY"   # key variant; omit for OAuth
```

### Cursor

Open this one-click install link (generated by `scripts/make-cursor-deeplink.mjs`):

```
cursor://anysphere.cursor-deeplink/mcp/install?name=needwing&config=eyJ0eXBlIjoiaHR0cCIsInVybCI6Imh0dHBzOi8vbmVlZHdpbmcuYWkvbWNwIn0%3D
```

or paste into `~/.cursor/mcp.json` (key variant shown; delete `headers` for OAuth):

```json
{
  "mcpServers": {
    "needwing": {
      "url": "https://needwing.ai/mcp",
      "headers": { "Authorization": "Bearer ${env:NEEDWING_API_KEY}" }
    }
  }
}
```

### Gemini CLI

```bash
gemini extensions install https://github.com/actionflow-team/needwing-plugins
```

(or install from a local clone: `gemini extensions install ./gemini-extension`). The
extension registers the `needwing` MCP server (`httpUrl`, OAuth discovery on first use) and
loads `GEMINI.md` context with the Needwing research instructions. Key variant — add
`"headers": {"Authorization": "Bearer YOUR_KEY"}` to the `needwing` entry in
`gemini-extension.json` when installing from a local copy.

### Claude Code key variant

The bundled `.mcp.json` has no headers, so Claude Code runs OAuth. To use a static key
instead, edit the installed `needwing` server (or a project `.mcp.json`) to:

```json
{
  "mcpServers": {
    "needwing": {
      "type": "http",
      "url": "https://needwing.ai/mcp",
      "headers": { "Authorization": "Bearer ${NEEDWING_API_KEY}" }
    }
  }
}
```

`${NEEDWING_API_KEY}` is expanded from your environment
([MCP docs](https://code.claude.com/docs/en/mcp)); set it before starting Claude Code. Never
commit a literal key.

## Repository layout

```
.claude-plugin/marketplace.json      Claude Code marketplace (plugin "needwing")
.agents/plugins/marketplace.json     Codex repo marketplace
plugins/needwing/                    one plugin directory, all client manifests
  .claude-plugin/plugin.json         Claude Code manifest
  .codex-plugin/plugin.json          Codex manifest
  .cursor-plugin/plugin.json         Cursor manifest
  .mcp.json                          MCP server config (Claude Code + Codex)
  skills/needwing/SKILL.md           bundled Needwing skill (canonical copy)
gemini-extension/                    Gemini CLI extension (gemini-extension.json + GEMINI.md)
server.json                          MCP Registry entry (ai.needwing/needwing)
scripts/                             validate / sync-skill / make-cursor-deeplink
docs/                                sources, publishing runbook
```

`npm test` validates every manifest: JSON parsing, required fields per format, that every
MCP URL equals the fixed endpoint, that the bundled skill matches the hash in
`skills.lock.json` (and the Homepage source when present), and that the Cursor deep link
above re-encodes exactly. Requires Node.js ≥ 24, no dependencies.

The bundled skill is the canonical served skill (`GET /api/connect/skill`). Re-sync it after
upstream changes with:

```bash
NODE_USE_ENV_PROXY=1 npm run sync-skill          # fetch from needwing.ai and update
node scripts/sync-skill.mjs --from-source        # offline: copy from the Homepage source tree
```
